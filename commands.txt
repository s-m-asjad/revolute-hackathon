wrist roll range fix (rotate leader 180, follower only does 90):
this is the one that limits how far the gripper assembly rotates. wrist_roll is capped
at (-90, 90) on BOTH sides -- teleop.joint_ranges on the leader and robot.joint_limits
on the follower. the leader reads 180, _round_to_valid_range leaves it at 180, then
_clamp(180, -90, 90) cuts it to 90. so the follower stops at half. both sides have to be
widened together, raising only one just re-clips at the other. append both flags:

--robot.joint_limits="{shoulder_pan: [-145.0, 145.0], shoulder_lift: [-0.0, 170.0], elbow_flex: [-0.0, 200.0], wrist_flex: [-80.0, 90.0], wrist_yaw: [-90.0, 90.0], wrist_roll: [-180.0, 180.0], gripper: [-0.0, 270.0]}" --teleop.joint_ranges="{shoulder_pan: [-150, 150], shoulder_lift: [-1, 170], elbow_flex: [-200, 1], wrist_flex: [-80, 90], wrist_yaw: [-90, 90], wrist_roll: [-180, 180], gripper: [-0, 270]}"

use square brackets not parens -- the parser splits on the comma inside parens and fails.

+-180 is the ceiling without a code change. _round_to_valid_range in
rebot_arm_102_leader.py folds every reading into a 360-wide window centred on
(min+max)/2, so anything past 180 wraps back around. continuous roll needs that function
changed, not just config.

CAUTION: unlike the gripper scale below, this DOES raise what gets commanded to the
hardware. before using it, check the b601 manual that wrist_roll really has +-180 of
travel, and watch the wrist camera cable -- rolling that far can wrap or strain it. worth
trying +-135 first and stepping up.

gripper travel fix (separate issue -- jaw open/close, not rotation):
the follower multiplies the leader's gripper angle by joint_directions["gripper"]=6.0
and then clamps the result to joint_limits["gripper"]=(0,270). so only the first 45
degrees of leader travel (270/6) does anything -- past that the command is pinned at
the clamp. dropping the scale to 3.0 spreads the same 0-270 follower range across 90
degrees of leader travel instead. the clamp, torque limit and mit gains are untouched,
so the commanded envelope is identical -- only the mapping gets gentler (3 deg/deg
instead of 6). append to the teleop or record command:

--robot.joint_directions="{shoulder_pan: 1.0, shoulder_lift: 1.0, elbow_flex: -1.0, wrist_flex: -1.0, wrist_yaw: -1.0, wrist_roll: 1.0, gripper: 3.0}"

note this does not make the gripper track position properly. the rs gripper goes
through send_mit(0, 0, 0, 1.5, tau_ff) with kp=0, so it is torque controlled and the
torque saturates once position error passes ~48 deg (torque_limit 10.0 / kp 12.0). the
flag widens where the closing command ramps, it does not turn it into a position servo.

untested on hardware -- verified the flag parses and lands in the config, nothing more.
try one teleop run before recording episodes.
